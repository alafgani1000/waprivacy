WA Privacy Shield Architecture

Technical documentation, security philosophy, and guidelines for contributing to the extension.

1. Architecture Overview

WA Privacy Shield is built strictly using Vanilla JavaScript, HTML, and CSS under the Manifest V3 architecture. We deliberately avoid heavy frameworks (like React or Vue) or build tools (like Webpack) to ensure the extension footprint remains below 50KB and executes instantaneously upon page load.

  • content.js / content.css: injected directly into web.whatsapp.com. It manages DOM state and CSS filter injections.
  • popup.html / popup.js: acts as the control interface. It communicates exclusively via local Chrome storage.
  • No Background Scripts: We do not use persistent background service workers, freeing up browser memory entirely when the popup is closed.

2. Zero-Connection Security Model

The core ethos of this project is absolute user privacy. As such, we adhere to a strict Zero-Connection rule:

  • No external CDNs are allowed (all fonts use System UI stacks).
  • No analytics or tracking scripts (e.g., Google Analytics, Mixpanel).
  • No `fetch()` or `XMLHttpRequest` calls anywhere in the codebase.
  • Data is saved using only chrome.storage.local.

3. Local Validation & CI/CD

We provide a local static analysis script (validate.js) to ensure no developer accidentally introduces external requests or violates the Manifest V3 constraints.

# Run the validator locally before committing
$ node validate.js

=== WA Privacy Shield Validator ===
✔ manifest.json is valid
✔ Zero external API calls detected
✔ Zero remote CDNs or fonts detected
🎉 SUCCESS

This same validator is integrated into our GitHub Actions. Additionally, the repository is configured to automatically deploy this website to GitHub Pages, and package `.zip` releases when new version tags are pushed to GitHub.

4. How the Blur Logic Works

Instead of heavy DOM manipulation, the extension simply attaches dynamic CSS classes (e.g., .wa-blur-messages) to the <body> element. The heavy lifting of targeting specific WhatsApp CSS selector trees is handled entirely by content.css using native CSS filters.

/* Example from content.css */
body.wa-privacy-active.wa-blur-messages div[data-testid="msg-container"] {
  filter: blur(8px);
  transition: filter 0.3s ease;
}
